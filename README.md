# Telegram VPN Sync

Автоматически берёт подписку из последнего поста Telegram-канала.

Источник:

https://t.me/happvpn

## Ключевой принцип

Домен источника НЕ захардкожен.

Например сегодня пост может содержать:

```text
happ://crypt5/...
https://chyra.ru/exec?...
tg://proxy?...
```

Будет выбрано:

```text
https://chyra.ru/exec?...
```

А если завтра будет:

```text
happ://crypt5/...
https://another-site.example/sub/123
tg://proxy?...
```

будет выбрано:

```text
https://another-site.example/sub/123
```

Если послезавтра будет IP:

```text
http://77.110.104.181:5002/sub/abc
```

будет выбран именно он.

Никакой проверки на `chyra.ru` нет.

## Remarks

Флаг определяется из исходного `remarks` (или из `countryCode`, который проставил GeoIP).

```text
🇮🇱 Израиль @RadexVPN
```

становится:

```text
🇮🇱 Израиль №1
```

Серверы «обход глушилок» (в `remarks` есть `LTE` как отдельное слово, `обход`, `глушил`, `bypass`, `censor`, `anti-block`) **не публикуются**, отдельного автосервера для них тоже нет.

Остаётся один автоматический сервер:

```text
🇪🇺 АВТО №1 ⚡
```

## Независимые серверы (`servers/`)

Любой `.json` из папки `servers/` попадает в подписку **в самый конец** и остаётся там, пока вы сами не удалите файл.
Такие серверы не берутся из Telegram, не проверяются GeoIP, не переименовываются и не входят в АВТО.

В файле может быть один конфиг, массив конфигов или `{ "configs": [...] }`. Если `remarks` не задан, берётся имя файла.

Порядок задаёт `servers/other-order.json` — массив имён файлов (с `.json` или без) либо `remarks`:

```json
["my-server", "backup.json", "🏳 Мой сервер"]
```

Перечисленное идёт первым и в этом порядке, остальное — по имени файла.
Битый JSON в `servers/` останавливает обновление, чтобы сервер не пропал из подписки молча.

## Определение страны (GeoIP)

Для каждого узла запускается Xray и через него запрашивается реальная страна выхода. Порядок источников:

1. `geo-overrides.json` в корне (необязательный, `{ "1.2.3.4": "DE", "host.example": "NL" }`);
2. реальная страна выхода через Xray;
3. кэш `data/geo-cache.json` (его коммитит Actions);
4. страна IP самого сервера — только если у конфига нет своей страны.

Узел, который не отвечает несколько запусков подряд (`GEO_DEAD_AFTER`, по умолчанию 2), убирается из подписки. Если не отвечает большинство узлов сразу, ничего не удаляется.
Переменные: `GEO_XRAY=off` (без Xray), `XRAY_BIN`, `GEO_XRAY_BUDGET_MS`, `GEO_EXIT_URLS`, `GEO_IP_URLS`, `GEO_BATCH_URL`.

## GitHub Actions

Запускается каждые 15 минут или вручную.

1. Открывает последний публичный пост.
2. Находит HTTP(S)-ссылки.
3. Берёт первую.
4. Скачивает файл.
5. Разбирает JSON.
6. Убирает серверы «обход глушилок», определяет страны (GeoIP), меняет remarks.
7. Добавляет в конец серверы из `servers/`.
8. Записывает `data/subscription.json`, `public/subscription.json` и `public/sub.txt`.
9. Валидирует результат.
10. Делает commit и push (включая `data/geo-cache.json`).
